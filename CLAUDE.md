# Betting Prediction — упатство за Claude (се чита автоматски)

Проект за статистичка анализа и предвидување за **NBA, Евролига и Еврокуп** (кладилница: Mozzart).
**Цел:** точни веројатности → долгорочно да ја победиме кладилницата → постојано подобрување.
Сопственик: Томе. Комуникација: **на македонски**, топло; стручните термини објасни ги едноставно со пример; биди критичен (не се согласувај само за да му биде убаво); кажи колку си сигурен и кој е најголемиот ризик; ако згрешиш — признај веднаш и кажи што менуваш.

## Редослед на читање (пред секоја работа)
1. `docs/PROCES.md` — ЗОШТО и КАКО (мисија, метрики, дневен процес, метод тим→играч, подобрување, грешки).
2. `docs/BUILD_PROMPT.md` — ШТО се гради (извори, формули, модел, правила, фази, CLI).
3. `docs/PLAN.md` — КАДЕ сме (статус на фази, одлуки, отворени прашања, дневник).
4. `docs/znaenje/` — детално знаење по тема (види BUILD_PROMPT §10 кое за која фаза).
5. `docs/LLM_ISTRAZUVACI.md` — бесплатните LLM како истражувачи (задолжително **од Фаза 6**).

## Неменливи правила
- **Python е единствениот извор на бројки.** Не пресметувај веројатности/проекции од глава — пушти го кодот и прочитај го резултатот. Ако кодот уште не го прави тоа → кажи го и предложи да го додадеме.
- **Никогаш не измислувај податок.** Недостасува → `None` + ознака во извештајот.
- **Прво тим, па играч.** Пазарот (Mozzart) влегува дури на крајот (против anchoring).
- Само бесплатни извори. Сè се кешира во `data/raw/`.
- Логови по датум. Играч = презиме + иницијал + тим.
- Не бриши архива. Не менувај `p_model` по натпревар. Сите избори се запишуваат, и одбиените.
- Промена на модел само преку backtest (PROCES §6.4). Ново правило не од 1–2 случаи.
- По секоја завршена задача → ажурирај `docs/PLAN.md` (статус + дневник: датум, што, зошто).
- Пред голема промена на архитектурата → прашај го Томе.
- Ништо не се уплаќа автоматски; одлуката е на Томе.
- **Бесплатните LLM (FreeLLMAPI) = само extract (T1/T2/T3/T10) — никогаш анализа.** Носат информации со извор + цитат; не даваат проценти/проекции/мислење, не бираат. Python го валидира секој нивни одговор. **`llm dnevno` / `llm site` се пуштаат САМО рачно кога Томе ќе каже** (не од Task Scheduler / `dnevno`).
- **Тајминг: една главна сесија 3–6 ч пред првиот натпревар**, уплата веднаш. Неизвесен статус → `ЗАВИСИ_ОД_СОСТАВ` → не во главен тикет. `proveri` е опционален.

## Окружување
Windows, VS Code, Python 3.10+, venv во `venv/`. Стартување: `python main.py ...` (BUILD_PROMPT §7).

## Режим „НИТРО“ (Томе 1.11 — важи секогаш)
Кога Томе ќе напише **„НИТРО [натпревар/тим/лига/денес]“**:
1. Claude **сам** пребарува (WebSearch), без FreeLLMAPI, само за тимовите од тие натпревари: повреди и состави (официјален извештај прв), новинари/beat, изјави на тренер, ротација, договори/трејдови од последните 48 ч.
2. Изворите ги симнува **Python** (не WebFetch — тоа е резиме, не страница): `research.nitro.download` → `data/raw/vesti/nitro/izvori/`. Цитатот се копира буквално од симнатиот текст.
3. Фактите → `data/raw/vesti/nitro/<датум>/<ознака>_vlez.json` (`liga`, `natprevari` ["LAL-TOR"], `prebaruvanja`, `fakti`: `tim, tip, igrac, sto, status?, prichina?, izvor_url, citat, objaveno`). Без извор = не се запишува.
4. `python main.py nitro <vlez.json>` → проверки како T1/T10 (цитатот во текстот, играчот во официјалниот состав, датум, без бројки/веројатности) → `vesti.md` со `IZVOR=CLAUDE_NITRO` → статуси (48 ч) во `data/vesti/<датум>.yaml` → линии ако ги нема → `povredi` → `picks`. Извештај: `reports/nitro/`.
5. **Никакви бројки/веројатности од Claude** — минути и picks се читаат од Python извештаите.
6. Лимит **~15 пребарувања** по НИТРО; за повеќе → прашај го Томе.
7. Одговор: **најмногу 15 реда** — OUT/Q по тим, кој ги зема минутите, промени во picks.
Без „НИТРО“ → вестите остануваат на FreeLLMAPI како досега.
