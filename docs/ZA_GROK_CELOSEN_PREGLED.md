## 3. Филозофија (неменливи правила)

1. **Python = вистина.** Ист влез = ист излез.
2. **Никогаш не измислувај податок** → `None` + ознака, не погодувај.
3. **Прво тим, па играч.** Пазарот (Mozzart) влегува **на крај** (anti-anchoring).
4. Само **бесплатни** извори; сè се **кешира** во `data/raw/`.
5. Промена на модел **само преку backtest** (walk-forward, без look-ahead).
6. Ништо не се уплаќа автоматски; `picks` по default е **режим на хартија**.
7. **Двете страни:** секогаш НАД и ПОД (не само „плус“).
8. Разлика модел↔пазар **> 15 pp** ИЛИ **EV > +15%** → `ПРОВЕРИ_ПОДАТОЦИ` (најчесто наша грешка).
9. Тајминг: **една сесија 3–6 ч пред првиот натпревар**; без задолжително „1 ч пред“. Неизвесно → `ЗАВИСИ_ОД_СОСТАВ` → не во главен тикет.
10. Комуникација со Томе: **македонски**.

## 5. Што има од ПОДАТОЦИ (особено играчи)

### 5.1 Играчки логови (најважниот датасет)

По лига и сезона во `data/processed/<лига>/<сезона>/player_logs.csv`.

**Колони (заедничка шема):**  
`season, game_code, round, phase, date_utc, game_date, date_local, team, opp, home, player_code, player, label, dorsal, starter, dnp, absence_reason, minutes, pts, fgm2, fga2, fgm3, fga3, ftm, fta, oreb, dreb, reb, ast, stl, tov, blk, …, pf, pir, fgm, fga, plus_minus`

- Играч се идентификува по **`player_code`** (не само „Презиме И.“ — близнаци итн.).
- Ознака за читање: `Презиме И. (ТИМ)`.
- DNP / Inactive + `absence_reason` (NBA има причини; ЕЛ често само DNP).
- Минути како децимални (пр. 25.32).

**Приближни големини (на дискот сега):**

| Лига | Сезони на дискот | player_logs (пример) |
|---|---|---|
| NBA | 2024-25, 2025-26, 2026-27 (+ backtest CSV) | ~4.2 MB / мината сезона; тековна помали |
| Евролига | E2024, E2025, E2026 | ~1.5–1.8 MB / сезона |
| Еврокуп | U2024, U2025, U2026 | ~0.8–0.85 MB / сезона |

Исто има: `team_logs.csv`, `schedule.csv`, `roster.csv`, сезонски табели (`season_players_*`, `season_teams_*`).

### 5.2 Raw кеш

- `data/raw/<лига>/boxscore/<сезона>/…` — box score **еднаш** по завршен натпревар  
- `data/raw/<лига>/<датум>/` — распоред/статистики/состави по ден  
- `data/raw/nba/injury/` — NBA injury PDF  
- `data/raw/mozzart/ДАТУМ/…` и `data/raw/evrotip/ДАТУМ/…` — снимки на линии (`.json.gz`)  
- `data/raw/vesti/` — симнати вести за LLM  

### 5.3 Линии (нормализирани)

`data/processed/linii/ДАТУМ.csv` — кладилница, натпревар, играч, пазар, страна, линија, квота, главна линија.

### 5.4 Архива на избори

`archive/izbori.db` (+ csv) — сите picks (CEKA/DA/NE/VOID/ODBIEN/DUPLIKAT…), со `p_model`, квота, EV, CLV, `vlezovi_json`, итн.  
Стара рачна архива: `data/archive/*.csv` (мигрирана).

### 5.5 Профили на тимови

`data/timovi/{nba|euroleague|eurocup}/{тим}/` — **82 тима** (30+20+32).  
- **БРОЈКИ** = Python неделно (`profil`)  
- **ОПИС/ПРОМЕНИ** = предлози од LLM → валидација → Томе `profil odobri`

### 5.6 Што се пресметува по играч (модел, не само raw)

Од `player_logs` + тимски контекст:

| Параметар | Како |
|---|---|
| Минути | форма (half-life 8), скалирана така што тимот = 240 мин NBA / 200 ЕЛ-ЕК (**M2**) |
| Стапка/мин | поени, reb, ast, 3PM… + shrinkage кон просек на позиција (~75 псевдо-минути) |
| DvP | одбрана по позиција што противникот ја дозволува (тежина 50%, капа ±15%/±12%) |
| Отсуства | НОВО vs СТАРО (играл ли во последните 3); ефект = прераспределба на минути преку M2 |
| Распределба | negative binomial (r по пазар / опсег); поени често нормална со σ од резидуали |
| P(НАД) и P(ПОД) | двете страни; потоа калибрација, па пазар |

**Отфрлено во backtest:** „70% иста позиција + usage пренасочување“ (M3) — систематски +1.3…1.9 мин кај соиграчите.

Детално знаење за параметри: `docs/znaenje/kosharka-igraci-parametri.md`.

## 6. Модели (кратко)

### 6.1 Тимски (Фаза 4 — готово)

- Влезови: pace/поседи, ORtg/DRtg (прилагодени), Four Factors, форма, пренос меѓу сезони (prior).  
- Избор по лига од walk-forward: **ЕЛ = V3**, **NBA = V4**, **ЕК = V4** (слаб доказ).  
- Одмор/B2B и Four Factors како додаток — **исклучени** (не помагаат вон примерок).  
- NBA главни тотали/хендикепи ≈ пазар → **нема јасна предност** таму; тимскиот модел е основа за сценарио + играчи.

### 6.2 Играчки (Фаза 5 — готово)

- M2 минути + per-minute + DvP + NB распределба.  
- Калибрација на синтетички линии е ориентир; **вистинска предност** се мери со зачувани Mozzart линии (од ~29.10.2026).

### 6.3 Пазар (Фаза 7 v1 — хартија)

Проекција **без** линија → P → калибрација (ЕЛ привремено `EL_STEGNUVANJE_50`: p → 0.5 + 0.5·(p−0.5)) → de-vig (**пропорционален**) → EV → филтри → тикет 2–3 (¼ Kelly, капа 2%, само евиденција) → запис CEKA.

```

```

### 8.3 Задачи (каталог)

| Код | Што | Статус / употреба |
|---|---|---|

| T2 | Експертски превјуа | Фаза 7 |

### 8.4 Режим НИТРО (Claude/Cursor, не FreeLLM)

Кога Томе ќе напише **„НИТРО [натпревар]“**: агентот бара вести (WebSearch), Python ги симнува страниците (`research.nitro`), валидира како T1/T10, па `python main.py nitro <vlez.json>` → picks. Агентот **не** дава бројки — ги чита од Python извештаи. Лимит ~15 пребарувања.

## 14. Брз „ментален модел“ за играч

```
Кои се тимовите? → темпо, ORtg/DRtg, сценарио (блиско / blowout)
Кој е OUT (НОВО)? → кој ги зема минутите (M2: тим = 240/200)
μ = минути × стапка/мин × DvP × …
P(НАД), P(ПОД) од распределба → калибрација
ДУРИ ПОТОА Mozzart линија → de-vig → EV
Филтри → тикет 2–3 или ОДБИЕН со име на правило
```

Предност ја бараме кај: **ново отсуство**, **играчки пазари ЕЛ/ЕК**, **ПОД на надуени ѕвезди**, **ast ПОД кај не-главен носител**, **ѕид vs ѕид тотал ПОД**.  
Тешко: NBA главни спредови/тотали без ново отсуство.
